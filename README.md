# Farsi_RTL

راست‌چین‌سازی هوشمند برای چت‌بات‌های هوش مصنوعی، به‌علاوهٔ فونت Vazirmatn.

Smart right-to-left rendering for AI chat sites, plus the Vazirmatn font.
The detection works for Persian, Arabic, Hebrew, Urdu and Pashto.

![icon](icons/icon128.png)

## چه کاری می‌کند

مدل‌های هوش مصنوعی فارسی را با اصطلاح‌های انگلیسی قاطی می‌نویسند، و مرورگر
نمی‌داند هر پاراگراف به چه زبانی نوشته شده. نتیجه‌اش این است که یک جواب فارسی
چپ‌چین می‌شود، نقطه و علامت سؤال سر جای غلط می‌افتند، و جدول‌ها برعکس خوانده
می‌شوند.

این افزونه برای هر پاراگراف تصمیم می‌گیرد، و مهم‌تر از آن، تصمیمش را طوری
می‌گیرد که به طول کلمه‌ها و به ترتیب پردازش صفحه وابسته نباشد.

## ویژگی‌ها

- **سه حالت راست‌چین** — هوشمند (تشخیص خودکار برای هر پاراگراف)، همیشه (هر
  پاراگرافی که فارسی داشته باشد)، هیچ‌وقت (جهت دست‌نخورده؛ فقط فونت و اصلاح bidi).
- **کادر تایپ** — وقتی فارسی می‌نویسی، کادر پرامپت هم راست‌چین می‌شود. محتوای
  پرامپت هرگز دست‌کاری نمی‌شود.
- **جدول‌ها** — ترتیب ستون‌ها در جدول فارسی برعکس می‌شود، نه فقط تراز سلول‌ها.
- **فونت Vazirmatn** (اختیاری) در سه وزن، و **فاصلهٔ سطرها**ی بازتر برای خوانایی.
- **اصلاح دستی** — متن یک پاراگراف را انتخاب کن و دکمهٔ سبز کنارش را بزن تا
  جهتش برعکس شود. میان‌بر `Alt+Shift+F` هم همین کار را می‌کند. این اصلاح‌ها
  ذخیره می‌شوند و بعد از رفرش هم باقی می‌مانند.
- **سوییچ هر سایت** — اگر روی یک سایت اذیت کرد، همان‌جا خاموشش کن. خاموش یعنی
  واقعاً خاموش: هر چیزی که افزونه به صفحه اضافه کرده برداشته می‌شود.
- **کپی تمیز** — متن کپی‌شده هیچ کاراکتر نامرئی ندارد.
- **حالت تشخیص** — برای توسعه: هر پاراگراف را با رنگ علامت می‌زند و می‌گوید کدام
  قاعده روی آن فایر شده، و می‌تواند تصمیم‌های کل صفحه را به‌صورت JSON کپی کند.

## تشخیص جهت چطور کار می‌کند

سؤال این نیست که «کدام زبان بیشترِ این پاراگراف را گرفته»، بلکه این است که
«این پاراگراف به چه زبانی *نوشته* شده». شمردن حروف جواب نمی‌دهد، چون
`isAnnotationPresent()` نوزده رأی برای انگلیسی است و «متد» سه رأی برای فارسی —
با آن حساب «متد `getClass()`» درست درمی‌آید و «متد `isAnnotationPresent()`»
برعکس، فقط به‌خاطر طول یک شناسه.

پس اول کد داخل بک‌تیک و لینک‌ها کنار گذاشته می‌شوند — یک شناسه داخل `code` شیء
خارجی‌ای است که در جمله افتاده، نه زبانی که جمله با آن نوشته شده. بعد آنچه
می‌ماند با قاعده‌هایی سنجیده می‌شود که به طول حساس نیستند:

| # | قاعده | نتیجه |
|---|---|---|
| ۱ | نثر فارسی ندارد | دست نزن |
| ۲ | نثر لاتین ندارد | RTL |
| ۳ | نثر با فارسی شروع شده | RTL |
| ۴ | کلمات فارسی ≥ لاتین | RTL |
| ۵ | فارسی بین دو ران لاتین | RTL |
| ۶ | جملهٔ انگلیسی با دنبالهٔ فارسی | LTR |
| ۷ | لاتین‌محور ولی فقط یک اصطلاح | RTL |

قاعدهٔ ۳ همان قاعدهٔ first-strong پشت `dir="auto"` است. قاعدهٔ ۴ کلمه می‌شمارد
نه حرف، پس یک شناسهٔ بلند یک رأی است. قاعدهٔ ۵ به «Compile Time و Runtime» جواب
می‌دهد: کلمهٔ فارسی که بین دو کلمهٔ لاتین گیر کرده، شیئی نیست که جمله درباره‌اش
حرف می‌زند، مفصلی است که جمله روی آن ساخته شده.

تصمیم‌گیری کاملاً همگام و قطعی است — همان پاراگراف همیشه همان جواب را می‌گیرد.

## نصب دستی (Load unpacked)

1. آخرین زیپ را از [Releases](https://github.com/alimirzad/Farsi_RTL/releases) بگیر و باز کن
2. به `chrome://extensions/` برو
3. **Developer mode** را روشن کن
4. **Load unpacked** را بزن و پوشهٔ بازشده را انتخاب کن

بعد از هر به‌روزرسانی، افزونه را reload کن **و تب‌های باز را یک بار رفرش کن** —
کانتنت‌اسکریپت نسخهٔ قبلی در تب‌های باز زنده می‌ماند.

## توسعه

```
engine.js     تصمیم زبان — توابع خالص، بدون DOM
match.js      تطبیق الگوی سایت — توابع خالص
content.js    لایهٔ DOM: مشاهده، علامت‌گذاری، ایزوله‌کردن، تشخیص
popup.js      تنظیمات
background.js فقط رلهٔ میان‌بر صفحه‌کلید
tools/        اجراگر دقت و مجموعهٔ تست
```

`engine.js` و `match.js` عمداً بدون DOM نوشته شده‌اند تا همان کدی که در مرورگر
اجرا می‌شود مستقیماً در Node تست شود:

```bash
node tools/accuracy.js            # دقت روی مجموعهٔ تست
node tools/accuracy.js --verbose  # با جزئیات هر مورد
node tools/match.test.js          # تطبیق الگوی سایت‌ها
```

### بزرگ‌کردن مجموعهٔ تست

حالت تشخیص را از فوتر پاپ‌آپ روشن کن، یک گفتگوی واقعی را باز کن، **کپی JSON**
را بزن، هر جایی که موتور اشتباه کرده `expect` را درست کن، و فایل را بده به
اجراگر:

```bash
node tools/accuracy.js harvested.json
```

نکتهٔ مهم: مقدار `expect` در خروجی، جوابِ خودِ موتور است. اگر بدون بازبینی
اضافه شود، دقت به‌طور خودکار ۱۰۰٪ می‌شود و هیچ معنایی ندارد.
